`/katrinalaszlo/personal-site` is a static personal site that doubles as an agent-readable knowledge base, publishing profile data, notebook content, Agent Skills, and a small MCP server from local files.

## The Problem

- Human-friendly sites are usually hard for agents to discover because the structured surfaces are missing or inconsistent.
- Notes and essays are readable in the browser, but they are not easy to query programmatically without a search layer.
- Adding machine-readable endpoints often pushes a simple site into unnecessary frameworks, databases, or build tooling.
- Teams need one source of truth for profile data, notebook content, and agent-facing metadata instead of maintaining parallel systems.

## The Solution

This repository stays static-first. The homepage and notebook are plain HTML, the profile is duplicated into `llms.txt` and `agents.json`, discovery metadata lives under `.well-known/`, and [`api/mcp.js`](/workspace/home/personal-site/api/mcp.js) turns the local notebook plus Agent Skills into a JSON-RPC MCP endpoint.

```bash
curl -X POST https://katrinalaszlo.com/api/mcp \
  -H 'Content-Type: application/json' \
  -d '{
    "jsonrpc": "2.0",
    "id": 1,
    "method": "tools/call",
    "params": {
      "name": "query_notebook",
      "arguments": {
        "query": "agent self-serve implementation checklist"
      }
    }
  }'
```

The server reads local files, strips markup from notebook pages, scores matches by simple term overlap, and returns the best matching notebook pages, skills, and reference snippets.

## Quick Start

The minimum working example is the MCP handshake followed by a tool call.

```bash
curl -X POST https://katrinalaszlo.com/api/mcp \
  -H 'Content-Type: application/json' \
  -d '{
    "jsonrpc": "2.0",
    "id": 1,
    "method": "initialize"
  }'
```

Expected output:

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "protocolVersion": "2024-11-05",
    "serverInfo": {
      "name": "katrinalaszlo-notebook",
      "version": "1.0.0"
    },
    "capabilities": {
      "tools": {
        "listChanged": false
      }
    }
  }
}
```

Then list the tool surface:

```bash
curl -X POST https://katrinalaszlo.com/api/mcp \
  -H 'Content-Type: application/json' \
  -d '{
    "jsonrpc": "2.0",
    "id": 2,
    "method": "tools/list"
  }'
```

From there, call `query_notebook`, `list_topics`, or `get_skill`.

## Key Features

- Plain HTML site with no framework, dependency tree, or build step, as described in [`CLAUDE.md`](/workspace/home/personal-site/CLAUDE.md).
- Multiple machine-readable endpoints: `llms.txt`, `llms-full.txt`, `agents.json`, `.well-known/ai-plugin.json`, `.well-known/agent-card.json`, `.well-known/api-catalog`, and `.well-known/mcp/server-card.json`.
- Local-file-backed MCP server that searches notebook pages and Agent Skills at runtime from [`api/mcp.js`](/workspace/home/personal-site/api/mcp.js).
- Agent Skills discovery via [`.well-known/agent-skills/index.json`](/workspace/home/personal-site/.well-known/agent-skills/index.json).
- Reusable notebook navigation generated by [`notebook/nav.js`](/workspace/home/personal-site/notebook/nav.js).
